# VK AI Assistant — бот-помощник на vkbottle

Интеллектуальный AI-ассистент внутри ВКонтакте: несколько диалогов, краткосрочная
память, шесть ролей общения, ответы от Gemini или любой OpenAI-совместимой модели
через ProxyAPI.ru и режим «Менеджер по базе знаний» (RAG) с поиском по загруженным
документам. Хранилище профилей вынесено в отдельный **MCP-сервер** — бот не
читает и не пишет JSON-файлы напрямую.

## Возможности

- **Многодиалоговость** — до 20 диалогов на пользователя, сортировка по дате,
  переключение, переименование, очистка и удаление с inline-подтверждением.
- **Шесть ролей общения**: обычный помощник, программист, преподаватель,
  бизнес-консультант, дружелюбный собеседник, менеджер по базе знаний.
- **База знаний (RAG)** — файлы прайс-листов и регламентов индексируются
  эмбеддингами, бот отвечает по ним и не выдумывает факты.
- **Краткосрочная память** — последние 100 сообщений активного диалога
  (и до 14 000 символов) попадают в контекст запроса к модели.
- **Fallback по моделям** — если основная модель недоступна, запрос уходит
  в резервную; при полном сбое пользователю показывается понятная ошибка,
  а неудачный обмен не сохраняется в историю.
- **Имитация набора текста** — `messages.setActivity(type="typing")` плюс
  сообщение «🤔 Думаю…», которое редактируется в первый кусок ответа.
- **Защита интерфейса** — пустые и слишком длинные сообщения, неизвестные
  команды, устаревшие кнопки, сетевые сбои.
- **Полностью русский интерфейс** и клавиатуры VK.

## Команды и кнопки

Текстовые команды:

| Команда | Действие |
| --- | --- |
| `/start` | Открыть главное меню и показать активный диалог с его режимом |
| `/help` | Справка по возможностям и кнопкам |
| `/cancel` | Выйти из ввода названия и вернуться в меню |

Любая неизвестная команда возвращает подсказку открыть `/start`.

Постоянная клавиатура (текстовые кнопки, видны всегда):

| Кнопка | Что делает |
| --- | --- |
| ➕ Новый диалог | Создаёт `Диалог N` и делает его активным |
| 📂 Мои диалоги | Список диалогов по 4 на страницу с переключением и удалением |
| ⚙️ Настройки | Активный диалог, режим, модель, число сообщений + действия |
| 🎭 Сменить режим | Выбор одной из шести ролей для текущего диалога |
| ❓ Помощь | Текст справки |
| 📚 База знаний | Показывает размер RAG-контейнера (появляется, когда индекс не пуст) |

Действия inline-кнопок (callback payload → обработчик в `bot/handlers/callbacks.py`):

| `cmd` | Поведение |
| --- | --- |
| `menu` | Вернуться в главное меню, снять состояние FSM |
| `dialogs`, `dialogs_page` | Открыть список диалогов / перейти на страницу |
| `dialog_open` | Сделать диалог активным |
| `dialog_rename` | Перевести в состояние ожидания нового названия |
| `dialog_delete` → `dialog_delete_confirm` | Запрос подтверждения и удаление |
| `dialog_clear` → `dialog_clear_confirm` | Очистка истории без удаления диалога |
| `settings`, `modes`, `mode_set` | Экран настроек, экран режимов, смена роли |
| `retry` | Повторить последний неудачный запрос к модели |
| `noop` | Закрыть неактуальную клавиатуру без изменений |

## Архитектура

```
VK (LongPoll) ──> bot/  ──> services/  ──> services/providers/ ──> ProxyAPI (LLM)
                     │            │
                     │            └──> storage/client/ ──MCP──> storage/server/ ──> data/users/*.json
                     └── keyboards/, config/
```

Бот общается с хранилищем **только через MCP-инструменты** (`ping`, `get_user`,
`save_user`, `delete_user`, `list_users`, `storage_stats`). MCP-сессия живёт в
отдельной задаче-акторе с автопереподключением: один оборот соединения не роняет бота.

| Путь | Назначение |

## Быстрый старт

Нужен Python 3.12+.

```bash
python -m venv venv
venv\Scripts\activate            # Windows
pip install -r requirements.txt  # + requirements-dev.txt для тестов

copy .env.example .env           # затем заполнить значения
python run_all.py                # поднимает MCP-сервер и бота
```

`run_all.py` запускает MCP-сервер отдельным процессом, ждёт открытия порта и стартует
бота. Если сервер уже запущен, используется он.

Отдельные команды:

```bash
python run_mcp.py    # только MCP-сервер хранилища
python run_bot.py    # только бот (сервер должен работать)
```

| `MCP_HOST`, `MCP_PORT`, `MCP_PATH` | Адрес сервера хранилища |

Полный список с комментариями — в `.env.example`.

### Получение токена VK

Сообщество → Управление → Работа с API → Ключи доступа → «Создать ключ».
Обязательно отметьте **два** права:

- **Сообщения** (`messages`) — читать и писать в диалоги;
- **Управление сообществом** (`manage`) — без него VK не отдаёт сервер Long Poll.

Должно быть включено само сообщество-бот: Настройки → Сообщения → «Сообщения сообщества
включены», и Long Poll API с типом события «личные сообщения».

Нехватка права выглядит как невнятный `VKAPIError_15: Access denied`. Перед запуском
Long Poll бот проверяет ключ и пишет по-русски, чего именно не хватает
(`check_vk_token()` в `bot/main.py`):

```
Бот не запущен: Сообщество доступно, но у ключа нет права «Управление сообществом» (manage).
```

## Смена модели

Модель выбирается в `.env` и читается один раз при старте. Через кнопки в VK модель
не меняется — это решение администратора, в «Настройках» она только показывается.

### Порядок обращения к моделям

Один запрос к боту = максимум две попытки (`services/ai_service.py`):

```
основная модель ──успех──> ответ
      │ ошибка / таймаут / пустой ответ
резервная модель ──успех──> ответ
      │ ошибка
AIUnavailableError ──> «не получилось, попробуйте ещё раз» + кнопка 🔄
```

Резервная модель вызывается **только при сбое** основной. При штатной работе она
не расходуется. Неудачный обмен в историю диалога не сохраняется.

### `AI_PROVIDER` — это транспорт, а не вендор

| Значение | Транспорт | Для каких моделей |
| --- | --- | --- |
| `openai` | OpenAI SDK → `https://api.proxyapi.ru/v1` | всё, что отдаёт OpenAI-совместимый `/v1` |
| `gemini` | Google GenAI SDK → `/v1beta` | модели Gemini нативным API |

### Подключение любой модели из каталога ProxyAPI

Каталог ProxyAPI отдаёт около 800 моделей, и почти все они говорят по
OpenAI-совместимому протоколу. Такая модель подключается **правкой `.env`, без
изменения кода** — `OpenAICompatProvider` принимает любое имя строкой:

```
AI_PROVIDER=openai
OPENAI_MODEL=x-ai/grok-4.3
OPENAI_FALLBACK_MODEL=deepseek/deepseek-chat
```

Примеры префиксов из каталога (полный список — `GET /v1/models`):

| Вендор | Префикс | Пример имени |
| --- | --- | --- |
| xAI (Grok) | `x-ai/` | `x-ai/grok-4.3` |
| OpenAI | `openai/` | `openai/gpt-4.1-mini` |
| Anthropic | `anthropic/` | `anthropic/claude-haiku-4-5` |
| Google | `google/` | `google/gemini-3.1-flash-lite` |
| DeepSeek | `deepseek/` | `deepseek/deepseek-chat` |
| Alibaba | `qwen/` | `qwen/qwen-2.5-coder-32b-instruct` |
| Meta | `meta-llama/` | `meta-llama/llama-3.3-70b-instruct` |
| Mistral | `mistralai/` | `mistralai/codestral-2508` |

Проверить конкретную модель, не запуская бота:

```bash
python scripts/smoke_ai.py --provider openai --model x-ai/grok-4.3
```

### Когда код править всё-таки придётся

| Ситуация | Что делать |
| --- | --- |
| Модель ProxyAPI с OpenAI-совместимым `/v1` | Только `.env` |
| Gemini нативным API | Только `.env` (`AI_PROVIDER=gemini`) |
| Прямой API стороннего провайдера в обход ProxyAPI | Новый класс в `services/providers/` + ветка в `AIService._build_provider()` |
| Провайдер с нестандартной схемой ответа | То же самое |

### Оговорка про эмбеддинги

Эмбеддинги для базы знаний **не зависят от `AI_PROVIDER`**: `services/rag_service.py`
всегда ходит в OpenAI-совместимый `/v1/embeddings` с моделью из `EMBEDDING_MODEL`.
При `AI_PROVIDER=gemini` ответы будут идти от Gemini, а поиск по базе знаний — по-прежнему
через `openai/text-embedding-3-small`. Это осознанно: эмбеддингов Gemini у ProxyAPI нет.

## База знаний (RAG)

Режим «📚 Менеджер по базе знаний» нужен, чтобы бот отвечал клиентам строго по вашим
документам — прайс-листам, описаниям тарифов, регламентам — и не додумывал цены.

### Индексация файлов

Индексация идёт через CLI: файлы готовит менеджер с компьютера, а не через чат в VK.

```bash
python scripts/rag_index.py --add price.txt "docs/регламент.pdf"   # добавить файлы
python scripts/rag_index.py                                        # проиндексировать весь каталог
python scripts/rag_index.py --status                               # размер и источники
python scripts/rag_index.py --find "сколько стоит тариф старт"     # проверить поиск
python scripts/rag_index.py --clear                                # очистить индекс
```

Поддерживаются `.txt`, `.md`, `.csv`, `.log`, `.pdf`. Для PDF нужен
`pip install PyPDF2` — без него читаются только текстовые форматы, а на PDF бот
вернёт понятную подсказку.

Файлы-источники лежат в `data/users/rag/sources/`, индекс — в
`data/users/rag/chunks.json`. Оба пути можно переопределить флагом `--sources`.
После индексации бота нужно перезапустить: индекс читается один раз при старте.
Кнопка «📚 База знаний» в главном меню показывает актуальное число чанков и список
источников.

Настройки в `.env`: `RAG_ENABLED`, `EMBEDDING_MODEL`, `RAG_TOP_K`.

### Как контекст подмешивается в ответ

Это главное в режиме, и происходит оно на **каждый** новый вопрос:

```
вопрос пользователя
   │  1. векторизуется той же моделью, что и документы
   ▼
cosine similarity по всем чанкам                    services/rag_service.py:search()
   │  2. берётся RAG_TOP_K ближайших по смыслу
   ▼
блок «[1] (путь/файл)\nтекст чанка …»               chat_service.py:_format_rag_context()
   │  3. приклеивается к системному промпту
   ▼
ДОКУМЕНТЫ ДЛЯ ОТВЕТА: …                             prompts.py:build_system_prompt()
   │  4. вместе с историей диалога уходит в модель
   ▼
ответ со ссылкой на источник
```

Детали, которые стоит знать:

- **Чанкинг** — текст режется на куски по 500 слов с перекрытием в 100 слов
  (`CHUNK_SIZE` / `CHUNK_OVERLAP` в `services/rag_service.py`). Перекрытие нужно,
  чтобы фраза про цену не оказалась разорвана между двумя чанками.
- **Поиск по всему вопросу целиком**, без пересборки запроса и без rerank:
  косинусное расстояние считается по всем чанкам линейно. На базах до нескольких
  тысяч чанков это доли секунды, на десятках тысяч станет заметно — тогда стоит
  перейти на numpy или готовый векторный индекс.
- **Порога похожести нет.** В топ всегда попадают `RAG_TOP_K` ближайших фрагментов,
  даже если вопрос совсем о другом. Удерживать модель от выдумок поэтому должен
  промпт режима: он прямо запрещает отвечать без опоры на документы и требует
  фразы «в моих материалах нет информации по этому вопросу».
- **Роль в промпте — системная**, история диалога передаётся как обычно. То есть
  найденные фрагменты не накапливаются: на каждый ход они подбираются заново.
- **Индекс пуст** — режим деградирует нормально: `rag_context` остаётся пустым,
  промпт не дополняется, и бот честно говорит, что материалов нет.

Проверить подбор фрагментов без VK и без бота:

```bash
python scripts/rag_index.py --find "условия доставки"
```

### Ограничения текущей реализации

- индекс перечитывается только при старте бота — после `--add` нужен перезапуск;
- эмбеддинги считаются один раз и кэшируются в `chunks.json`, повторная индексация
  того же файла тратит токены только на новые чанки;
- `chunks.json` содержит содержимое ваших документов — каталог `data/users/rag/`
  исключён из git.


Покрыто: JSON-хранилище (атомарность, битые файлы), промпты, разделение длинного

## Ограничения VK, заложенные в код

- длина сообщения — 4096 символов, бот режет ответ на части (лимит `MAX_MESSAGE_CHARS`);
- inline-клавиатура — не больше 10 кнопок и 6 рядов, подпись — 40 символов,
  payload — 255 байт UTF-8; всё это валидируется до отправки;
- пустые сообщения и сообщения без текста игнорируются с подсказкой;
- `setActivity` требует токен сообщества с правом `messages`, индикатор живёт 5–10 секунд.

## Хранение данных

Профиль каждого пользователя — один файл `data/users/{user_id}.json`:
настройки, счётчик диалогов, активный диалог и полная история сообщений.
Запись атомарна (временный файл + `replace`), на пользователя действует async-локал.
Повреждённый JSON не ломает бота: файл сохраняется как `.corrupt-<timestamp>` и
создаётся чистый профиль.

База знаний живёт рядом — `data/users/rag/`: `sources/` с исходными файлами и
`chunks.json` с текстами и эмбеддингами. Всё это содержит персональные данные
клиентов и содержимое ваших документов, поэтому `data/users/` целиком исключён
из git; в репозитории только `.gitkeep`.

## Использованные технологии

- [vkbottle](https://vkbottle.tools/) 4.11 — VK Bot Long Poll
- [google-genai](https://pypi.org/project/google-genai/) — нативный SDK Gemini
- [openai](https://pypi.org/project/openai/) — OpenAI-совместимый клиент для ProxyAPI
- [mcp](https://modelcontextprotocol.io/) — сервер и клиент хранилища (Streamable HTTP)
- ProxyAPI.ru — единая точка доступа к Gemini и другим моделям
